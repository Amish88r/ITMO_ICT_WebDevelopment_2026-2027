# Выводы

В ходе работы реализованы клиент-серверные приложения на сокетах Python:

* **UDP** не требует соединения и подтверждений — достаточно `sendto()`/`recvfrom()`, но доставка
  не гарантируется.
* **TCP** требует установления соединения (`listen`/`accept`/`connect`), зато гарантирует доставку
  и порядок байт. Поскольку TCP — потоковый протокол, границы сообщений нужно задавать самостоятельно
  (в работе — JSON-строки с разделителем `\n`).
* **HTTP** — это текстовый протокол поверх TCP: строка статуса, заголовки, пустая строка и тело;
  корректный `Content-Length` считается в байтах.
* Для одновременной работы нескольких клиентов использованы **потоки** (`threading`); общие данные
  (список пользователей чата) защищены блокировкой `Lock`.
* Разбор HTTP-запросов вручную показывает, что делают за разработчика веб-фреймворки: чтение
  заголовков, определение метода и пути, дочитывание тела по `Content-Length`, формирование ответа.
